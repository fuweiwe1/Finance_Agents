# Goal 模式：按计划自主执行

你是这个项目的执行 agent。按以下规则工作，直到用户说"停"。

## 1. 加载计划与进度

1. 读取 `docs/PLAN.md`（已批准的实施计划：目标 G0–G6 / 里程碑 M0–M5 / 测试 T1–T4 / 优化）。
2. 读取进度文件 `.claude/goal-mode/progress.md`（不存在则初始化：`status: pending`）。
3. 用 TaskCreate/TaskUpdate 建立任务列表：当前里程碑各任务 + 测试任务。

## 2. 执行

- **目标里程碑**：`$ARGUMENTS` 指定了（如 `M3`）则跳到该里程碑；否则从 `progress.md` 里"下一个未完成里程碑"继续，**严格按 M0→M5 顺序**。
- 每个里程碑：
  1. 逐个完成任务（脚手架 → 数据层 → API+Agent → 前端 → 打磨 → 优化），写代码时遵循计划里的技术选型与架构，复用已存在函数/类型。
  2. **完成该里程碑后必须跑对应测试档位**（计划"七、测试方案"）：
     - M1/M2 → T1 单测 + T2 集成（Vitest）
     - M3 → T3 E2E（Playwright）
     - 每步先 `npm run typecheck` / `npm run lint` 保证静态检查绿。
  3. 测试有失败 → 修复后重跑，**不允许带着红灯进入下一里程碑**。
  4. 更新 `progress.md`（标记该里程碑 `done` + 一行验收证据，如"TSLA 真实数据解析通过"）。

## 3. 报告

每完成一个里程碑，用简洁中文汇报：
- 完成了什么（文件/接口/UI）
- 测试结果（哪些档位、通过与否、失败修复记录）
- 与计划的偏差（如有）及原因
- 下一里程碑是什么

## 4. 纪律

- 尊重计划里"九、风险与对策"（如腾讯字段解析器要 fixture 锁格式、Finnhub 无 key 降级）。
- 不在计划范围内的炫技/重构不做；发现计划需要调整时，先说明再改。
- 真实数据联调、或需要用户提供 key（Finnhub / 模型 API）时，说明需要什么、怎么拿，不阻塞的部分先用 mock/fixture 顶住。
